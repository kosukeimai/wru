# wru v4.0.0 — Development Handoff

This document is the starting point for a clean session. It records where v4.0.0
stands, the decisions that are locked, what remains, and the gotchas (especially
around testing) that will otherwise bite a fresh session.

## Goal of v4.0.0

Integrate the 2020 Census names data and replace the old surname-source switch
with a richer, explicit `name_source` control, while shipping the already-present
eBISG work. Concretely:

- Add 2020 Census-derived surname and (new) first-name dictionaries.
- Introduce `name_source = c("mixed", "census_only", "vf_only")` on `predict_race()`,
  deprecating the boolean `census.surname`.
- Remove dead legacy code and the now-unused bundled datasets.
- Fold in several open issues (#156, #162 done; #105, #150 pending).

## What is done (verified, pushed)

1. Phase 1 — `data-raw/build-name-dictionaries-2020.R` derives `census_last_c`
   (refresh) and `census_first_c` (new) from the standard 2020 Census
   names-by-race files. Output is P(name | race), columns sum to 1, schema matches
   the existing dictionaries. Validated: posteriors track the v2.0.0 dictionary
   within 1–2 points; the real surname "NA" is preserved.
2. Phases 4 and 5 — removed `.predict_race_old()`, `merge_surnames()`, the bundled
   `surnames2000`/`surnames2010` datasets and their docs, and the orphaned
   `test-race_prediction_funs.R`. Surname-only coverage is preserved by the
   existing 2010/2020 tests.
3. `R/name_source.R` — `stack_name_dictionary()` (the mixed/census_only/vf_only
   union with Census precedence and a `source` tag), `read_name_dictionaries()`
   (the single I/O seam, mockable), `load_name_dictionaries()` (assembles the
   first/middle/last dictionaries per `name_source`/`year`), and
   `resolve_name_source()` (maps deprecated `census.surname`).
4. Full `name_source` threading — `predict_race()` exposes `name_source`
   (`rlang::arg_match`, default `"mixed"`), `census.surname` defaults to `NULL` and
   warns + maps when supplied (`TRUE -> "mixed"`, `FALSE -> "vf_only"`). Threaded
   through `predict_race_new` / `predict_race_me` / `predict_race_embedding` into
   `merge_names`. The eBISG `known_surnames` set is loaded via
   `load_name_dictionaries()` so it agrees with the merge dictionary.
5. #156 — anchored the impute-step regex in `merge_names` to `^c_` so user columns
   containing `c_` are not swept into imputation.
6. #162 — `impute.missing = FALSE` now leaves unmatched names as `NA` (removed the
   `coalesce(., 1)` else branch) so callers can identify unmatched rows.

Verification observed: `test-predict_race_2010` (45), `test-predict_race_2020` (46),
`test-ebisg-bug-repro` (9), an fBISG smoke test, and the offline unit tests
(`test-name_source`, `test-load_name_dictionaries`, `test-resolve_name_source`,
`test-merge_names-offline`).

## Decisions that are locked

- Build dictionaries from the standard public 2020 files, not the "research"
  negatives-retained variant. The differential-privacy noise is at most a few units
  and the standard files already zero negatives and rebalance row totals losslessly.
- First-name strategy: keep the voter-file `first_c` and add a parallel
  `census_first_c`; do not replace (Census-only would drop ~85k rare first names).
- `name_source` semantics:
  - last: census_only -> census_last_c; vf_only -> last_c (augmented, documented as
    not strictly Census-free); mixed -> union(census_last_c, last_c), Census wins.
  - first: same pattern with census_first_c / first_c.
  - middle: always `mid_c`; `census_only` errors if middle names are requested
    (no Census middle dictionary exists).
- Default `name_source` is `"mixed"`. It is a strict superset of the old Census
  default, so predictions are unchanged for surnames present in the Census list and
  only gain coverage for names absent from Census but present in the voter-file dict.
- PR #165 (`return_unmatched` by @mdblocker) is superseded, not merged. Re-implement
  its `return.unmatched` feature inside our work (keep his param and `*_matched`
  column names for API compatibility), credit him, and close the PR when the
  replacement ships. See [v4-supersedes-pr165 memory].

## Remaining work (in suggested order)

### #105 — return.unmatched / matched-name flag

Re-implement PR #165's feature. In `merge_names`, after the cleaning cascade and
before imputation, compute per-name booleans
`df$<type>_matched <- !is.na(df$c_whi_<type>)`. Add a `return.unmatched = FALSE`
parameter; when `TRUE`, include the `last_matched` / `first_matched` /
`middle_matched` columns in every return path (there are several early and final
returns — this is the fiddly part PR #165 spent ~333 lines on). Thread
`return.unmatched` through `predict_race` and the three predictors, carrying the
flag columns into the final output (note `predict_race_new` returns
`voter.file[vars.orig]`, so the flag columns must be added explicitly or they get
dropped). Then close PR #165 with a comment crediting @mdblocker.

This is testable offline using the same `local_mocked_bindings(load_name_dictionaries = ...)`
pattern as `test-merge_names-offline.R`. Do the `merge_names` half first (clean,
self-contained), then the predictor threading.

### #150 — toggle the Census progress bar

The progress bars are `furrr::future_map_dfr(..., .progress = TRUE)` at
`R/census_geo_api.R:115` and `:195`. Thread a `verbose`/`progress` logical from

## How to develop and test (critical)

- The package compiles RcppArmadillo, so loading is slow; use
  `pkgload::load_all(".", quiet = TRUE)`.
- Mocked tests are gated by `skip_on_cran()`. Run them with `NOT_CRAN=true` in the
  environment, or they silently skip.
- The full network test suite hangs on the FIRST run because it downloads ~40 MB of
  dictionaries. After one run the files are cached in `tests/testthat/` (look for
  `All local files already up-to-date!`) and subsequent runs are fast (a single
  `predict_race` test file runs in ~8–15 s). The hang is NOT a code problem.
- The fBISG `test-rollup.R` runs multiple 1000-iteration Gibbs samplers and exceeds
  ~560 s. Do NOT use it for quick verification. Verify `predict_race_me` with a
  tiny-iteration smoke test instead:
  `predict_race(..., model = "fBISG", control = list(iter = 20, burnin = 10, verbose = FALSE))`.
- Offline unit testing pattern: mock `load_name_dictionaries` (or
  `read_name_dictionaries`) with `testthat::local_mocked_bindings(..., .package = "wru")`
  to feed tiny fixture dictionaries with no network. This is how `merge_names` and
  the loader are tested.
- Fast verification recipe:
  `NOT_CRAN=true Rscript -e 'options(wru_data_wd=TRUE); pkgload::load_all("."); testthat::test_file("tests/testthat/test-<name>.R")'`
